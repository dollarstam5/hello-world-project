Philosophie des API de Vitala

Les API de Vitala constituent le contrat officiel entre les domaines métier de la plateforme et les

différentes interfaces qui les utilisent.

Elles appliquent une approche API First, garantissant que chaque capacité métier est accessible à

travers un contrat stable, documenté et indépendant de l'interface utilisateur.

Les API représentent les capacités de la plateforme et non sa structure interne.

Principes fondamentaux

Domain First

Chaque API appartient à un domaine métier clairement identifié.

Les responsabilités ne sont jamais partagées entre plusieurs domaines.

Chaque domaine reste propriétaire exclusif de ses données.

Identity First

L'Unified Digital Identity (UDI) constitue la représentation officielle de l'utilisateur.

Les API ne modifient jamais directement les vues agrégées de l'UDI.

Chaque domaine publie ses propres données.

L'UDI agrège ensuite ces informations afin de construire une représentation cohérente destinée aux

interfaces.

Single Source of Truth

Chaque donnée possède une unique source de vérité.

Une donnée ne peut être modifiée que par le domaine qui en est propriétaire.

Toutes les autres API la consultent via les contrats appropriés.

Contract First

Chaque API est définie avant son implémentation.

Les contrats constituent la référence officielle pour les développeurs, les applications clientes et les

outils d'intelligence artificielle.

Stable Evolution

Les API sont conçues pour évoluer sans casser la compatibilité avec les clients existants.

Les nouvelles capacités sont ajoutées progressivement sans remettre en cause les contrats déjà publiés.

Offline First

Toutes les API sont conçues pour fonctionner avec la stratégie Offline First de Vitala.

Les opérations critiques peuvent être mises en attente, synchronisées ultérieurement et rejouées

lorsque la connectivité est rétablie.

Security by Design

Chaque API applique les principes de sécurité de la plateforme :

authentification ;

•

autorisation ;

•
•

contrôle des permissions ;
traçabilité ;

•

protection des données personnelles.

Event Ready

Même si le MVP repose principalement sur REST, les API sont conçues pour pouvoir évoluer vers une

architecture orientée événements sans modification majeure des contrats métier.

Relation avec les domaines métier

Les API ne contiennent pas la logique métier.

Elles orchestrent les échanges entre les interfaces et les domaines.

Chaque domaine applique ses propres règles avant de produire les données qui seront exposées.

2

Relation avec l'Unified Digital Identity

Les domaines métier produisent des informations.

L'Unified Digital Identity agrège ces informations sous forme de vues (Views).

Les interfaces consomment ces vues via les API appropriées.

Les API ne reconstruisent jamais elles-mêmes l'identité numérique.

Objectif

L'objectif de cette architecture est de fournir des contrats simples, stables et évolutifs permettant aux

applications clientes de consommer les capacités de Vitala sans dépendre de son implémentation

interne.

Cette approche garantit la pérennité de la plateforme, facilite l'évolution des domaines métier et

prépare l'intégration des futures applications web, mobiles et des services d'intelligence artificielle.
