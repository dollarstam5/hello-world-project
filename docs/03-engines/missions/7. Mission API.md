1. Mission

La Mission API est responsable de la création, de la gestion et du suivi des missions au sein de Vitala.

Une mission représente un objectif concret nécessitant la participation d'une ou plusieurs personnes

afin d'obtenir un résultat défini.

Contrairement à un Flash, qui exprime une intention, une mission représente un engagement structuré

avec un cycle de vie et des responsabilités clairement établis.

5. Objet métier

Mission

Une mission est une activité structurée possédant :

•

un objectif ;

•

un propriétaire ;

•

éventuellement des participants ;

•

un statut ;

•

des dates importantes ;

•

des critères de réussite ;

•

un niveau de visibilité.

Une mission peut être créée à partir d'un Flash, mais elle devient ensuite un objet métier autonome.

7. Règles métier (Business Rules)

•

Une mission possède un seul propriétaire.

•

Une mission ne peut être publiée que si les informations obligatoires sont renseignées.

•

Une mission terminée ne peut plus être modifiée, sauf selon les règles prévues par la

plateforme.

•

Chaque participation est historisée.

•

Une mission peut influencer le Trust des participants, mais uniquement par l'intermédiaire du

Trust Engine.

•

Une mission peut être détectée comme opportunité par le Radar Engine ou recommandée par le

Recommendation Engine.

9. Validation

Chaque mission est validée selon :

•

les champs obligatoires ;

•

son propriétaire ;

•

son statut ;

•

les droits d'accès ;

•

les règles métier de transition entre les états.

10. Sécurité

Seuls les utilisateurs autorisés peuvent créer, modifier ou administrer une mission.

Toutes les opérations sensibles sont :

•

authentifiées ;

•

autorisées ;

•

journalisées.

Les règles de visibilité déterminent quelles missions sont accessibles aux autres utilisateurs.

11. Dépendances

La Mission API dépend de :

•

Auth API ;

•

Unified Digital Identity API (identification du propriétaire) ;

•

Media API (pièces jointes éventuelles).

Elle ne dépend pas directement :

•

du Trust Engine ;

•

du Radar Engine ;

•

du Recommendation Engine ;

du Veille Engine.

13. Évolutions futures

Le domaine Mission est conçu pour évoluer avec :

•

des rôles avancés (chef de mission, participant, observateur) ;

•

des sous-missions ;

•

des jalons (milestones) ;

•

des livrables ;

•

des évaluations ;

•

des intégrations avec des organisations ou des projets.

Ces évolutions conserveront les mêmes contrats fondamentaux.
