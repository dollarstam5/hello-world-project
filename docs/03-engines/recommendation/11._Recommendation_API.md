API-CONTRACT-008 — Recommendation API

Version : V1

Statut : MVP

1. Mission

La Recommendation API expose les recommandations personnalisées produites par le

Recommendation Engine.

Son objectif est d'aider chaque utilisateur à prendre les meilleures décisions en fonction de son identité

numérique, de son contexte et des informations disponibles dans la plateforme.

La Recommendation API ne remplace jamais le choix de l'utilisateur.

Elle l'assiste dans sa prise de décision.

2. Position dans l'architecture

Interface

↓

Recommendation API

↓

Recommendation Domain

↓

Recommendation Engine

↓

Database

Le Recommendation Engine agrège des informations provenant de plusieurs domaines afin de produire

des recommandations personnalisées.

3. Responsabilités

La Recommendation API est responsable de :

•

exposer les recommandations personnalisées ;

•

expliquer les recommandations lorsque cela est possible ;

•

permettre leur consultation ;

•

enregistrer les réactions de l'utilisateur (acceptée, ignorée, masquée).

Elle ne crée jamais directement les recommandations.

Toutes les recommandations sont produites par le Recommendation Engine.

4. Capacités

L'API permet notamment :

•

consulter ses recommandations ;

•

consulter une recommandation détaillée ;

•

enregistrer une recommandation ;

•

masquer une recommandation ;

•

indiquer qu'une recommandation a été suivie ;

•

signaler une recommandation non pertinente.

5. Objet métier

Recommendation

Une Recommendation représente une action personnalisée proposée à un utilisateur.

Elle peut concerner :

•

une mission ;

•

un Flash ;

•

une opportunité détectée ;

•

une personne ;

•

une compétence ;

•

un contenu ;

•

une action à réaliser.

Chaque recommandation possède :

•

un score de pertinence ;

•

une priorité ;

•

une justification ;

•

une période de validité.

2

6. Règles métier (Business Rules)

•

Les recommandations sont exclusivement produites par le Recommendation Engine.

•

Les recommandations sont personnalisées pour chaque utilisateur.

•

Une recommandation doit pouvoir être justifiée.

•

Les recommandations respectent les paramètres de confidentialité.

•

Les réactions de l'utilisateur améliorent progressivement les futurs modèles de

recommandation.

7. Contrat REST

Endpoints principaux :

•

GET /recommendations

•

GET /recommendations/{id}

•

POST /recommendations/{id}/save

•

POST /recommendations/{id}/dismiss

•

POST /recommendations/{id}/accept

•

POST /recommendations/{id}/report

8. Validation

L'API vérifie :

•

les droits d'accès ;

•

la disponibilité de la recommandation ;

•

la cohérence des actions demandées ;

•

la validité de la période d'affichage.

9. Sécurité

Toutes les opérations nécessitent une authentification.

Les recommandations respectent :

•

les règles de confidentialité ;

•

les autorisations ;

•

les préférences de l'utilisateur ;

•

les politiques de sécurité de Vitala.

3

10. Dépendances

La Recommendation API dépend :

•

Recommendation Engine ;

•

Auth API ;

•

Unified Digital Identity API.

Le Recommendation Engine peut exploiter les informations issues des domaines :

•

Trust ;

•

Radar ;

•

Veille ;

•

Flash ;

•

Mission.

Chaque domaine reste propriétaire de ses données.

11. Événements produits

La Recommendation API publie notamment :

•

RecommendationViewed

•

RecommendationAccepted

•

RecommendationDismissed

•

RecommendationSaved

•

RecommendationReported

Ces événements permettent au Recommendation Engine d'améliorer progressivement la qualité de ses

recommandations.

12. Évolutions futures

Le domaine Recommendation pourra intégrer :

•

des modèles d'intelligence artificielle avancés ;

•

des recommandations prédictives ;

•

des recommandations collaboratives ;

•

des assistants intelligents ;

•

des recommandations multimodales.

Ces évolutions conserveront les mêmes contrats fondamentaux.
