API-CONTRACT-001 — Auth API

Version : V1

Statut : MVP

1. Mission

L'Auth API est responsable de l'authentification et de la gestion des sessions des utilisateurs de Vitala.

Elle constitue le point d'entrée sécurisé de la plateforme.

Son objectif est de permettre à un utilisateur de prouver son identité avant d'accéder aux

fonctionnalités de Vitala.

L'Auth API ne gère ni les informations de profil ni l'Unified Digital Identity (UDI). Elle fournit uniquement

une identité authentifiée qui sera utilisée par les autres domaines.

2. Responsabilités

L'Auth API est responsable de :

•

créer un compte utilisateur ;

•

authentifier un utilisateur ;

•

terminer une session (déconnexion) ;

•

renouveler une session ;

•

réinitialiser un mot de passe ;

•

vérifier une adresse e-mail ;

•

gérer les méthodes d'authentification ;

•

exposer l'identité authentifiée aux autres domaines.

Elle n'est jamais responsable du Trust, du profil, des préférences ou des données métier.

6. Contrat REST

Endpoints principaux :

•

POST /auth/register

•

POST /auth/login

•

POST /auth/logout

•

POST /auth/refresh

•

POST /auth/forgot-password

•

•

Toutes les réponses suivent le format standard des API Vitala.

7. Validation

Les règles de validation incluent notamment :

•

unicité de l'adresse e-mail ;

•

mot de passe conforme à la politique de sécurité ;

•

vérification des champs obligatoires ;

•

limitation des tentatives de connexion ;

•

validation des jetons de session.

8. Sécurité

L'Auth API applique les principes suivants :

•

authentification sécurisée ;

•

gestion des sessions ;

•

rotation des jetons ;

•

protection contre les attaques par force brute ;

•

limitation du débit (rate limiting) ;

•

journalisation des événements critiques.

9. Dépendances

L'Auth API dépend de :

•

système d'identité (Supabase Auth dans le MVP) ;

•

service d'e-mail ;

•

système de journalisation.

Elle ne dépend d'aucun domaine métier.

Les autres domaines dépendent d'elle.

11. Évolutions futures

L'architecture prévoit l'ajout de :

•

authentification multifacteur (MFA) ;

•

fournisseurs OAuth ;

•

authentification sans mot de passe (Passkeys) ;

•

authentification biométrique sur mobile ;

•

Ces évolutions n'impliqueront pas de modification des contrats fondamentaux.
