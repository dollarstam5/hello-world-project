API-CONTRACT-005 — Trust API

Version : V1

Statut : MVP

1. Mission

La Trust API expose les informations produites par le domaine Trust.

Elle permet aux interfaces et aux autres services de consulter les données de confiance d'un utilisateur

sans jamais modifier directement leur contenu.

Le Trust est exclusivement produit par le Trust Engine.

2. Position dans l'architecture

Interface

↓

Trust API

↓

Trust Domain

↓

Trust Engine

↓

Database

La Trust API constitue la façade officielle du domaine Trust.

1

3. Responsabilités

La Trust API est responsable de :

•

exposer le Trust Score ;

•

exposer le Trust Level ;

•

exposer la Trust View ;

•

exposer l'historique du Trust ;

•

exposer les Trust Evidence autorisées ;

•

expliquer les évolutions visibles du Trust.

Elle ne calcule jamais le Trust.

Elle ne modifie jamais le Trust.

4. Capacités

L'API permet notamment :

•

consulter son Trust ;

•

consulter son historique ;

•

consulter les badges obtenus ;

•

consulter les facteurs principaux influençant le Trust ;

•

consulter les preuves visibles (Trust Evidence) ;

•

consulter les évolutions récentes.

Toutes ces opérations sont en lecture.

5. Objet métier

Trust Profile

Le domaine Trust expose notamment :

•

Trust Score ;

•

Trust Level ;

•

historique ;

•

badges ;

•

progression ;

•

preuves visibles ;

•

évolution temporelle.

Ces informations sont produites par le Trust Engine.

2

6. Règles métier (Business Rules)

•

Le Trust appartient exclusivement au domaine Trust.

•

Aucun utilisateur ne peut modifier son Trust.

•

Aucune API externe ne peut modifier un Trust Score.

•

Les événements provenant des autres domaines sont analysés par le Trust Engine avant toute

évolution.

•

Toutes les évolutions sont historisées.

•

Les modèles de calcul peuvent évoluer sans modifier le contrat API.

7. Contrat REST

Endpoints principaux :

•

GET /trust/me

•

GET /trust/me/history

•

GET /trust/me/badges

•

GET /trust/me/evidence

•

GET /trust/me/progression

Aucun endpoint de modification directe n'est exposé.

8. Validation

Les validations portent notamment sur :

•

les droits d'accès ;

•

la visibilité des informations ;

•

les politiques de confidentialité ;

•

la cohérence des historiques exposés.

9. Sécurité

L'accès aux données de confiance respecte :

•

l'authentification ;

•

les autorisations ;

•

les paramètres de confidentialité ;

•

la protection contre la divulgation d'informations sensibles.

Certaines informations du Trust Engine peuvent rester volontairement non exposées.

3

10. Dépendances

La Trust API dépend :

•

du Trust Engine ;

•

de l'Auth API ;

•

de l'Unified Digital Identity API (pour l'identification de l'utilisateur).

Elle ne dépend d'aucun autre domaine métier.

Les autres domaines produisent uniquement des événements consommés par le Trust Engine.

11. Événements consommés

Le domaine Trust peut exploiter notamment :

•

FlashPublished

•

MissionCompleted

•

RecommendationValidated

•

CommunityValidation

•

ReportConfirmed

•

ActivityRecorded

Ces événements ne modifient jamais directement le Trust.

Ils sont analysés par le Trust Engine.

12. Événements produits

Le domaine Trust publie notamment :

•

TrustUpdated

•

TrustLevelChanged

•

BadgeAwarded

•

TrustEvidenceAdded

Ces événements peuvent être consommés par :

•

Unified Digital Identity ;

•

Notification API ;

•

Recommendation Engine.

13. Évolutions futures

Le domaine Trust pourra intégrer :

•

plusieurs modèles de calcul ;

différents niveaux de pondération ;

•

intelligence artificielle ;

•

recalcul global ;

•

modèles spécifiques par communauté.
