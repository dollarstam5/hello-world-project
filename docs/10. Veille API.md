API-CONTRACT-007 — Veille API

Version : V1

Statut : MVP

1. Mission

La Veille API expose les informations, alertes et évolutions détectées par le Veille Engine.

Son objectif est de tenir l'utilisateur informé des événements susceptibles d'avoir un impact sur ses

activités, ses missions, ses centres d'intérêt ou son réseau.

La Veille fonctionne de manière continue et proactive.

2. Position dans l'architecture

Interface

↓

Veille API

↓

Veille Domain

↓

↓

Le Veille Engine analyse les événements de la plateforme et les sources configurées afin de produire

des informations pertinentes.

1

3. Responsabilités

La Veille API est responsable de :

•

exposer les éléments de veille ;

•

présenter les alertes pertinentes ;

•

permettre leur consultation ;

•

gérer leur état (lu, non lu, ignoré, enregistré).

Elle ne produit jamais directement les analyses.

Toutes les analyses proviennent du Veille Engine.

4. Capacités

L'API permet notamment :

•

consulter son tableau de veille ;

•

consulter un élément de veille ;

•

marquer un élément comme lu ;

•

enregistrer un élément ;

•

ignorer un élément ;

•

signaler une information non pertinente.

5. Objet métier

Veille Item

Un Veille Item représente une information détectée automatiquement.

Il peut concerner :

•

une nouvelle mission ;

•

une évolution importante ;

•

une tendance ;

•

une activité pertinente ;

•

une évolution du réseau ;

•

un changement de Trust ;

•

un sujet suivi par l'utilisateur.

Chaque élément est accompagné d'un niveau de pertinence et d'une date de détection.

2

6. Règles métier (Business Rules)

•

Les éléments de veille sont exclusivement produits par le Veille Engine.

•

Aucun utilisateur ne peut créer directement un élément de veille.

•

Les informations présentées respectent les paramètres de confidentialité.

•

Les éléments peuvent être archivés ou ignorés sans être supprimés.

•

La Veille privilégie la qualité et la pertinence plutôt que la quantité.

7. Contrat REST

Endpoints principaux :

•

GET /veille

•

GET /veille/{id}

•

POST /veille/{id}/read

•

POST /veille/{id}/save

•

POST /veille/{id}/ignore

•

POST /veille/{id}/report

8. Validation

L'API vérifie :

•

les droits d'accès ;

•

la visibilité des informations ;

•

les préférences de veille de l'utilisateur ;

•

la cohérence des états (lu, enregistré, ignoré).

9. Sécurité

Toutes les opérations nécessitent une authentification.

Les informations exposées respectent :

•

les règles de confidentialité ;

•

les autorisations ;

•

les préférences utilisateur ;

•

les politiques de sécurité de la plateforme.

3

10. Dépendances

La Veille API dépend de :

•

Veille Engine ;

•

Auth API ;

•

Unified Digital Identity API.

Le Veille Engine peut analyser les événements provenant des domaines Flash, Mission, Trust, Radar et

Recommendation, sans jamais en devenir propriétaire.

11. Événements produits

La Veille API publie notamment :

•

VeilleItemViewed

•

VeilleItemSaved

•

VeilleItemIgnored

•

VeilleItemReported

Ces événements peuvent être utilisés pour améliorer les modèles de pertinence et les

recommandations.

12. Évolutions futures

Le domaine Veille pourra intégrer :

•

des sources externes d'information ;

•

une veille sectorielle avancée ;

•

une veille géographique ;

•

des analyses prédictives ;

•

des modèles d'intelligence artificielle.

Ces évolutions conserveront les mêmes contrats fondamentaux.
